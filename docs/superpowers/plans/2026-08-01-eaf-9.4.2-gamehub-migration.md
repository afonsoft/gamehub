# Plano de Migração GameHub — EAF 9.4.2 + Templates Angular/API

> **Para agentes:** usar `superpowers:executing-plans` ou `superpowers:subagent-driven-development` para executar este plano passo-a-passo. Os passos usam checkbox (`- [ ]`) para rastreamento.

**Objetivo:** Atualizar o GameHub para os módulos EAF 9.4.2 e migrar os ajustes dos templates `EAF/Templates/Api` e `EAF/Templates/Angular` para o `angular-admin` e a API do GameHub, concluindo os módulos administrativos pendentes (`MassNotifications`, `UserDelegations`, `Payments`) e os componentes de edição/assinatura que faltam.

**Arquitetura:** O back-end continua em .NET 10 + EAF/ABP, com os pacotes `Eaf.Middleware.*` atualizados para `9.4.2`. As novas entidades (`MassNotification`, `UserDelegation`, `SubscriptionPayment`, `SubscribableEdition`) são expostas no `GameHubDbContext` para que as migrations e os AppServices do EAF funcionem. O front-end `angular-admin` recebe os componentes, proxies, rotas e chaves de localização faltantes, copiados/adaptados do template EAF. Os AppServices e permissões já vêm nos pacotes NuGet; o trabalho é principalmente expor entidades, gerar migration, e fazer o front-end consumir os novos endpoints.

**Stack:** .NET 10, ASP.NET Core + ABP 10.5, EAF 9.4.2, PostgreSQL, EF Core, Angular 20, PrimeNG/Metronic, NSwag (manual por ora).

```csharp
public static bool IsDesignTime { get; set; }

private static void EnsureMigrated(DatabaseFacade database)
{
    if (IsDesignTime || SkipMigrate || _created)
        return;

    lock (_migrateLock)
    {
        if (_created)
            return;

        _created = true;
        try
        {
            if (!SkipMigrate)
            {
                LogHelper.Logger.Trace("Database Migrate started...");
                database.Migrate();
            }
        }
        catch (Exception ex)
        {
            _created = false;
            LogHelper.Logger.Warn("Database Migrate started Error ...", ex);
        }
    }
}
```

## Riscos e Observações

1. **Migrations:** `GameHubDbContext` possui muitas entidades do domínio GameHub. A migration gerada pode ser grande; revisar antes de aplicar em produção.
2. **Service proxies manuais:** O `nswag` npm 13.4.2 ainda depende de runtime .NET 7, indisponível na VM. Continuar copiando proxies manualmente do template EAF e ajustando URLs/imports.
3. **Permissões:** As constantes de permissão do EAF 9.4.2 devem ser verificadas; nomes podem variar levemente. Usar `MiddlewarePermissions` como referência.
4. **Entidades:** Verificar se `SubscriptionPayment`/`SubscribableEdition` possuem `TenantId` e índices corretos; ajustar `OnModelCreating` se o schema da migration falhar.
5. **Testes Angular:** Os novos componentes podem quebrar specs por providers faltantes; ajustar mocks conforme padrão existente.
6. **Metronic/PrimeNG:** Componentes copiados do template podem depender de classes/temas não presentes no GameHub. Verificar visualmente após `ng serve`.
